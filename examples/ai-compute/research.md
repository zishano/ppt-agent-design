## Research Brief

主题：AI 计算与传统数据中心计算的本质差异。
基线：用户仅提供标题与两套 PPT 制作体系的对比要求，没有提供具体硬件性能或成本数据。
读者与用途：面向技术与投资读者，作为两份同主题六页演示的共同事实材料；本文件只记录事实，不规定页序或风格。
范围：以事务型数据库作为传统在线计算代表，以神经网络训练与自回归语言模型服务作为 AI 代表。传统计算还包含科学计算、分析和批处理，AI 也不只包含语言模型，不应将代表性差异写成二元绝对判断。
待补缺口：事务与训练的计算契约；训练与推理分阶段机制；内存和互联约束；性能口径与服务目标；功率与成本证据边界。
外部来源：允许使用官方文档和代码中的公开说明，采用共用事实集，不制造实验数据。

## 计算契约与训练机制

- [F001] 事务型数据库的核心契约之一是原子性：多个步骤作为一个全有或全无的操作，中间状态对其他并发事务不可见。
  - 适用边界：传统计算以 OLTP 为代表，并非涵盖所有传统工作负载。
- [F002] PostgreSQL 的事务教程把持久性描述为：事务完成并被数据库确认后，结果不会因随后的崩溃而丢失。
  - 适用边界：说明事务语义，不代表所有数据库配置具有完全相同的持久化保证。
- [F003] 神经网络线性层以可学习权重执行仿射变换 y = xAᵀ + b；这是 AI 张量计算的一个具体例子。
  - 适用边界：不应推广为所有 AI 操作都是矩阵乘法。
- [F004] PyTorch DDP 为各进程保留模型副本，在反向传播时通过集合通信同步梯度，然后用这些梯度更新模型。
  - 适用边界：适用于数据并行训练，不代表所有训练范式。
- [F005] DDP 进程可位于同一机器或跨机器；模型太大无法装入单 GPU 时，可把数据并行与模型并行结合。
  - 适用边界：不要把增加卡数等同于线性加速。

## 推理分阶段、内存与并行策略

- [F006] vLLM 的调优文档区分通常偏计算受限的 prefill 和偏内存受限的 decode，并通过混合调度平衡两类操作。
  - 适用边界：这是典型倾向；实际瓶颈取决于模型、批量、上下文长度与硬件，不是绝对分类。
- [F007] Chunked prefill 将较大的 prefill 拆成小块，并可与 decode 请求混合成批；默认可用时优先调度 decode。
  - 适用边界：说明分阶段调度，不能由此声称任意环境均获得固定性能提升。
- [F008] 批处理 token 预算影响服务权衡：文档中较小预算有利于 token 间时延，较大预算可改善首 token 时延；具体参数需要测量。
  - 适用边界：这些建议有版本、负载与硬件适用边界；不把示例参数当通用最优值。
- [F009] KV cache 空间不足时，vLLM 可抢占请求并在空间恢复后重算；抢占和重算可能恶化端到端时延。
  - 适用边界：内存容量会影响并发和服务质量；不是只看峰值算力。
- [F010] 张量并行将每层模型参数分布到多个 GPU；它可降低单卡权重压力，但增加并行度也可能带来过多同步开销。
  - 适用边界：说明容量与通信的权衡，不是 GPU 越多越好。
- [F011] 流水线并行把模型层分配到不同 GPU，数据并行则复制整个模型到多组 GPU，分别处理请求批次。
  - 适用边界：模型装得下与吞吐扩展是不同目标。
- [F012] NCCL 提供 all-reduce、all-gather、reduce-scatter 等 GPU 集合通信，可跨单机和多机，并支持 PCIe、NVLink 及网络传输。
  - 适用边界：通信结构由并行方式和实际拓扑决定；不声称 AI 独占高性能互联。

## 硬件不是定义：CPU 也能运行 AI

- [F013] vLLM 提供 Intel/AMD x86、ARM AArch64、Apple silicon 等 CPU 后端，因此 AI 推理并不在定义上等同于 GPU 计算。
  - 适用边界：支持运行不等于所有模型、精度和功能在各平台一致，也不证明性能等价。
- [F018] vLLM CPU 后端同样提供 KV cache 容量设置，文档指出更大的缓存空间允许更多请求并行。
  - 适用边界：内存和并发问题不限于 GPU，容量配置仍须匹配硬件和使用模式。

## 服务质量与性能比较

- [F014] MLPerf Inference 将服务端场景的性能与时延约束关联；离线场景则衡量吞吐，不能不加区分地比较两者。
  - 适用边界：采用方法论而非引用某一硬件跑分。
- [F015] MLPerf 的 LLM 基准同时定义 TTFT 与 TPOT：前者是首 token 时延，后者是输出 token 的平均间隔。
  - 适用边界：TPOT 是平均间隔，不等同于每个 token 间隔分布或尾时延。
- [F016] MLPerf 的封闭基准定义质量与时延目标；推理性能比较需要同时说明模型、任务、质量及服务约束。
  - 适用边界：不能仅凭 token/s 或 FLOPS 判断业务有效产出；本研究没有成本实测。

## 功率及证据边界

- [F017] NVIDIA DCGM 的 GPU 集群管理能力包含健康监测、诊断以及功率和时钟管理。
  - 适用边界：可支持把功率作为运维与测量维度；不能推出具体机柜功率、PUE 或液冷必要性。
