# 实体机器与机柜组成图：整机—部件对应工作流

适用于真实世界的机器、机柜、服务器、设备、板卡及其装配组成说明。目标是让读者在同一页回答：这是什么完整设备、由哪些部分组成、各有多少、位于哪里、如何连接、各自做什么。该规则补充分层机制图合同；不替代证据规则，也不把所有流程图改成硬件插画。

## 默认构图：左侧整机，右侧分层详情

这是用户已确认的组成图形式。不是“总览一页、详情另几页”，也不是把几个散件放在左侧就称为整体。

- 左侧约 45%：一台完整设备的立体结构。保留统一轮廓、承载结构、底座、安装层次及可理解的空间关系。按真实证据选择完整外观、局部剖切或爆炸图；有实际柜体时不能用几排无柜体的长条代替机柜。
- 需要爆炸展开时，各部件沿真实装配方向对齐，保留共用基准、轮廓和适度间距，使读者能想象它们装回同一设备。只有关系得到支持时才画统一底座、框架或外壳，不为“像整机”虚构机械结构。
- 右侧约 55%：按左侧部件顺序纵向分层。每层包含局部立体图或原厂细节图、部件名、整机内数量、部件内部组成、关键参数和作用。三层只是本次案例，层数取决于实际机器。
- 左右采用相同编号、颜色和引线。引线终止在对应对象或安装位置，不穿过文字；交叉不代表电气相连。装配引线与信号流箭头分开表达。
- 先看完整设备，再沿编号查看局部。信息过多时保留这一页完整的整体—部件对应图，再增加补充详情页；不要默认拆掉用户要求的同页关系。

上下层叠是本次案例的表达方式，不是所有机器的真实安装方向。禁止把示意布局推定成实际装配。

## 1. 调研与证据边界

先查原厂产品页、数据表、技术文档、实物照片或拆解资料；必要时补充有明确出处的博客及研究报道。实际阅读来源并保存定位，不以搜索摘要或用户参考图上的文字代替核查。

分别记录：

1. 目标机器已确认的外观、部件与参数。
2. 报道中的开发方案或未被官方确认的配置。
3. 参考平台的外观、单元组成与参数。
4. 尚未公开的尺寸、安装方向、接口位置、部件块数等。

不能把参考平台当作目标机器实物，不能把多个转载视为独立证据。用户图片用于风格与构图参考，其中的参数仍须核实。目标机器缺少公开实物资料时，先展示已知结构；只有获得示意绘制授权时才补解释性装配图，并在图上标明具体哪些外形、位置或方向属于示意。不得只靠备注中的免责声明掩盖虚构结构。

## 2. 先做部件表，再画图

在 evidence ledger 与 deck map 中保留每个部件的稳定 ID，至少记录：

| 字段 | 用途 |
| --- | --- |
| 部件名、上级部件 ID | 明确归属与展开层级 |
| 整机数量、单部件内部数量、单位 | 区分“每托盘”与“整柜” |
| 计算式与输入事实 ID | 核查合计，不能由插画猜数量 |
| 位置、朝向、连接对象与关系类型 | 区分机械安装、电气连接、液路及逻辑关系 |
| 作用与关键参数 | 只保留解释该结构所需信息 |
| 来源 ID、适用型号/代际、证据状态 | 防止跨型号拼参数 |
| 外观参考、图中编号、左右元素 ID | 保证整机与局部一致 |
| 未知项、可见限定语、示意授权 | 防止用默认值填空 |

中板“84 层”描述 PCB 层数，不是部件块数；画出一块板不证明整机只有一块。总量乘法要写清适用平台，例如参考平台的每托盘芯片数不能自动升级为目标机器的完整 BOM。

## 3. 静态立体技术插画制作

“动画风格”指静态的立体工程插画、CAD 风格或清晰的卡通化技术表现，不是 GIF、视频或 PowerPoint 动效。保留真实机器的比例特征、安装层次、板卡位置和关键连接，简化材质与背景，不简化掉决定结构的细节。

根据证据选择原厂图、可追溯的模型渲染或以真实图为依据的图像生成/编辑。绘图后端是实现选择：原有 python-pptx 机制图示例不限制机器插画使用图像工具。图像生成不能补造事实。生成图必须人工检查，文字、数量和元件位置不能因画面漂亮而免检。

优先将插画作为图像，参数、编号、引线和来源作为可编辑 PPT 元素。若整页采用静态图片，应明确其编辑限制，不宣称部件可独立编辑。

反复出现的单元有两种合法画法：逐个展示且数量正确；或明确标注“阵列缩略示意”，以经过核实的数量标签表达总数。局部展开用于解释内部数量时，芯片数必须与标签一致。无源中板不能画成带 CPU/GPU 的计算板；未公开的走线、接口、孔位不得冒充真实布线或机械细节。

不要给目标机器补装未经证实的风扇、硬盘、PDU、冷却管路、供应商部件、尺寸或机柜 U 数。参考图中的卫星级散热器、系统级功率等不能移植为单柜参数。

## 4. 验收与回退

先检查事实与结构，再检查美观：

- 左侧在缩略图尺寸下是否仍能识别为一台完整设备，而非零散物件或抽象连接网？
- 爆炸开的部件是否沿一致基准组成同一设备，装配方向是否有证据或清楚标为示意？
- 右侧是否逐一对应左侧部件，且给出了数量、内部结构和作用？
- 单部件与整机合计是否一致？生成图可见芯片数是否匹配？缩略阵列是否明确标注？
- 引线是否真的指向所命名的 CPU、GPU、连接器、中板或安装位？有无错位、穿字或误连？
- 实机、报道方案、参考平台和示意几何是否在页面上可区分？未知数量是否仍为“未披露/未核实”？
- 实际 PPTX 渲染是否文字清楚、比例正确、左右层级对应、来源可读？静态图是否被错误宣称可编辑？
- 是否只嵌入当前使用的静态素材？移除最终包中废弃的动态媒体及无用重复资源，压缩后复查标签清晰度，并报告文件大小。保留原始资料和历史版本，不将其全部塞进交付包。

只有散件、数量错误或整体关系不清，返回映射/绘制阶段；型号、参数或机械关系无依据，返回调研阶段。不能用增加框、芯片、装饰管线或免责声明替代修正。

## 本次确认样式的迁移原则

保留的是“左侧一台整机的立体/分层爆炸图 + 右侧逐层细节 + 数量参数 + 编号引线”的表达方式，不是 Kessel 的 18/9/84 等特定数字，也不是其示意外壳。下次面对另一种机器，重新核实部件与空间结构，再使用这一构图。
