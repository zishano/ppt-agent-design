# 绘制风格选择

两种独立风格并存，通过现有四阶段 skill 执行，不新增阶段，不自动互相替换。

| 名称 / ID | 渲染方式 | 可编辑范围 | 调用示例 |
| --- | --- | --- | --- |
| [机制插画风格](mechanism-illustrated.zh-CN.md) `mechanism-illustrated` | `integrated-static-illustration`：完整静态技术插画 | 主图含图中文字和路径不可逐部件编辑；页脚与备注可编辑 | “用机制插画风格生成……” |
| [可编辑机制图风格](mechanism-editable.zh-CN.md) `mechanism-editable` | `native-editable-illustration`：原生对象组合 | 文字、部件、队列、数据块、路径可编辑，设备可取消组合 | “用可编辑机制图风格生成……” |

## 选择规则

- 明确叫“机制插画风格 / 机制插画版”：选择原来的完整静态插画，保留原来的规则与画风；如实说明主图编辑限制。
- 明确叫“可编辑机制图 / 可编辑机制插画 / 原生可编辑版”，或要求“机制插画且必须能修改文字与部件”：选择 `mechanism-editable`。这是选择另一种风格，不是改写原风格。
- 仅要求“PPT 可编辑”时不能默认整页图片；按原有原生制作规则处理。未指名这两种风格时，不强制套用它们。
- 要求两版对比时，各建独立修订目录，共用证据范围，分别记录风格与编辑性；不得混淆交付名称。
- 用户同时要求“完全保留原图画面”和“所有细节原生可编辑”时，说明重建的视觉与编辑取舍，仅在其确实影响交付且无法据上下文判断时澄清；不能承诺无损转换。

brief.json 必须记录 `visual_style`、`render_mode`、`editability` 和参考版。映射、制作与验证只应用所选分支的编辑性合同。两者共同遵守事实来源、语义映射、实际渲染和项目输出目录规则。

可编辑分支后续单独优化材质、图元库、分组和连接能力。历史 PPT 与验证记录保持不变。
